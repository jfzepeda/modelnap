# Napkin: permisos e inicio/parada

## Correcciones

- El nombre visible y el producto ahora son Napkin, con identidad `com.jfzepeda.Napkin`. El cambio de identidad requiere conceder permisos de nuevo y no transfiere las preferencias anteriores.
- El monitor activo exigía además el preflight de escucha pasiva antes de intentar crear el event tap. Ahora requiere Accessibility y verifica que el tap activo esté habilitado. Se vuelve a comprobar la autorización al iniciar y durante el ticker. La interfaz distingue permiso ausente de monitor no operativo.
- Un error de monitor quedaba retenido después de recuperar permisos. Se recupera USER ACTIVE después de verificar permisos y completar la limpieza. Los errores de terminación y otros errores no se borran por esa recuperación.
- Mouse-up/key-up contaban como una nueva interacción. Una prueba reprodujo cuatro aserciones fallidas antes del cambio. Ahora se consumen las liberaciones correspondientes a eventos interceptados, pero las demás no cancelan Start.
- Se comprueba generación/cancelación después de las esperas de estado del proceso, evitando publicar AI ACTIVE o errores desde una transición obsoleta.
- Stop repetido durante la limpieza no borra errores ni inicia otro cierre. Los botones indican Starting/Stopping y se deshabilitan según la operación. Start cierra el panel.
- Se añadieron todas las resoluciones del icono macOS.

## Validación

14 pruebas pasan, incluidas recuperación de permisos simulada, liberación del control de inicio, Stop repetido durante arranque, dos ciclos completos con Ollama real, bloqueo HTTP 503 y terminación exclusiva de grupos propios. `git diff --check` pasa.

Release universal arm64/x86_64, macOS 14+, Hardened Runtime, firmado con Apple Development. `codesign --verify --deep --strict` verifica la firma y su designated requirement. Archivo: `dist/Napkin-1.0-macOS.zip`.

No es una distribución Developer ID notarizada. Falta verificar interactivamente el otorgamiento/revocación real de Accessibility a la copia instalada y la interrupción del overlay en la sesión del usuario. Los tests de permisos usan un monitor simulado y no conceden permisos del sistema. Los ciclos de Ollama no cargan modelos.

Advertencia preexistente: el argumento predeterminado de `InferenceGateway.init` referencia una propiedad aislada al main actor; el compilador advierte que será error en modo Swift 6. No se modificó fuera del alcance de estos fallos.

Referencia: Apple distingue [filtro activo defaultTap](https://developer.apple.com/documentation/coregraphics/cgeventtapoptions/defaulttap) de [escucha pasiva listenOnly](https://developer.apple.com/documentation/coregraphics/cgeventtapoptions/listenonly).

## Seguimiento: permiso activado pero denegado

La sesión real mostró en el registro TCC `Failed to match existing code requirement` para Accessibility y `com.jfzepeda.Napkin`. El permiso retenía un requisito basado en cdhash de una compilación anterior, mientras la copia en ejecución usaba la firma Apple Development. Se cerró la app normalmente, se restableció únicamente Accessibility de ese bundle con tccutil y se reabrió la misma copia firmada. El usuario volvió a conceder el permiso y confirmó que la app lo reconoce.

Debug ahora utiliza `com.jfzepeda.Napkin.debug` y el nombre visible `Napkin Debug`; Release conserva `com.jfzepeda.Napkin` y `Napkin`. Las pruebas que arrancan el host Debug ya no comparten la identidad TCC del Release. No fue necesario recompilar ni reemplazar el Release para reparar el permiso existente.
